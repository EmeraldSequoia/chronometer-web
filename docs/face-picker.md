# Face Picker & Selected Faces

The face picker lets users select a subset of watch faces, arrange them in a custom order, and view only those faces in a dedicated grid page. The selection persists in LocalStorage (the `chronometer` namespace, via `app-state.ts`), so it survives across page navigations with a clean URL; it is also included in a **Share** link and falls back to the URL when storage is unavailable.

## Pages

| Page | Purpose |
|------|---------|
| `pick.html` | Face picker — select and reorder faces |
| `selected.html` | Custom grid showing only the user's selected faces |

Both are generated by `build.sh`. `selected.html` is built from `face-template.html` (same as `all.html`), while `pick.html` is a standalone page.

## URL Abbreviations

Each watch face has a 2-letter `urlAbbrev` attribute on its `<watch>` XML element. These abbreviations are concatenated to compactly encode the selection in the stored `picks` value (and in shared-link / fallback `picks` URL parameters).

| Face | Abbrev | Face | Abbrev |
|------|:------:|------|:------:|
| Babylon | `bb` | Basel | `bs` |
| Mauna Kea | `mk` | Firenze | `fi` |
| Haleakalā | `hk` | Venezia | `vz` |
| Hana | `hn` | Terra | `tr` |
| Chandra | `ch` | Miami | `mi` |
| Selene | `sl` | Gaia | `ga` |
| Geneva | `gn` | | |

The `urlAbbrev` is also stored in:
- `Watch` interface in `types.ts`
- `FaceData` interface in `engine-entry.ts`
- Auto-generated registration modules under `src/faces/generated/`

### Build-Time Uniqueness Check

`build.sh` scans all XML files for `urlAbbrev` attributes and fails the build if any duplicates are found. Any new face must have a unique 2-letter abbreviation.

## The `picks` Value

`picks` is a concatenation of 2-letter abbreviation codes with no separator
(e.g. `bbgntr` → Babylon, Geneva, Terra). It is stored in the `chronometer`
namespace and read/written through `app-state.ts` (`getState().picks` /
`setState({ picks })`). It appears as a `?picks=…` URL parameter only in a Share
link or under the URL fallback.

### Propagation

Because `picks` lives in LocalStorage (shared across all same-origin pages), it
no longer needs to ride the URL during navigation:

- `pick.html` (`pick-page.ts`) — writes the selection with `setState({ picks })`
  on Done, then navigates to `selected.html` (clean URL in storage mode)
- `selected.html` / `engine-entry.ts` — reads `getState().picks` to filter and
  order the faces; redirects to `pick.html` if none
- `url-state.ts` — `updateNavigationLinks()` routes the selected-faces link to
  `selected.html` vs `pick.html` based on whether picks exist; the source is
  injected via `setPicksProvider()` (app-state registers `() => getState().picks`)
- `index-page.ts` — `updateLinks()` routes the pick card the same way

In the URL fallback / shared-link cases the `picks` parameter is still carried in
the query string and parsed from there.

## Navigation Flow

```
index.html
  ├─ "All Faces" card ────────→ all.html (full grid)
  ├─ "Pick Faces" card ───────→ pick.html (if no picks)
  ├─ "Selected Faces" card ───→ selected.html (if picks exist)
  └─ Individual face card ────→ babylon.html, etc.

pick.html ──── Done ──────────→ selected.html?picks=...
selected.html ─ Edit Picks ──→ pick.html?picks=...
selected.html ─ Click face ──→ babylon.html?picks=...
babylon.html ── 2×2 icon ────→ selected.html (or pick.html if no picks)
babylon.html ── 3×3 icon ────→ all.html
```

### Navigation Icons on Face Pages

The `face-template.html` top bar has three nav icons (left to right):

| Icon | ID | Target |
|------|----|--------|
| 🏠 House | `#back-link` | `index.html` |
| 3×3 dots | `#all-faces-link` | `all.html` |
| 2×2 accent dots | `#selected-faces-link` | `selected.html` or `pick.html` (smart) |

The 2×2 icon uses accent-colored (`#5ca0d3`) dots and is always visible for discoverability. Its destination is set dynamically by `updateNavigationLinks()` in `url-state.ts`.

### Index Page Smart Card

The "Pick Faces" / "Selected Faces" card on `index.html` adapts at runtime:
- **No stored picks** → shows "Pick Faces", links to `pick.html`
- **Picks present** → shows "Selected Faces", links to `selected.html`

This logic is in `updateLinks()` in `index-page.ts`.

## Pick Page (`pick.html` + `pick-page.ts`)

A standalone page (does not use `face-template.html`) with its own inline CSS matching the app's dark theme.

### Layout

- **Header**: Home link, "PICK YOUR FACES" title, and action buttons (All, None, Reorder, Done)
- **Grid**: All 13 face thumbnails in a responsive flexbox (120px on phone → 180px on desktop)

### Selection UX

- Tapping a face toggles its selection
- Selected faces get a blue border and a numbered badge (1, 2, 3...)
- Unselected faces are dimmed (50% opacity)
- **All** button selects every face in default order
- **None** button clears the selection
- **Done** button navigates to `selected.html?picks=...`

### Reorder Sheet

The **Reorder** button (disabled when < 2 faces selected) opens a slide-down overlay panel:

- Slides in from the top with a 0.3s CSS transition
- Semi-transparent backdrop behind it
- Vertical list of selected faces, each row showing: thumbnail, name, drag handle (≡)
- **Drag to reorder**: Touch (`touchstart`/`touchmove`/`touchend`) and mouse (`mousedown`/`mousemove`/`mouseup`) support
- **Done** button closes the sheet and reorders the picker grid to match

Closing the sheet: tap the backdrop, press Escape, or tap the sheet's Done button.

### Grid Reordering

When the user arrives at the pick page with existing `picks` in the URL, or after using the reorder sheet, the grid is rearranged: **selected faces appear first** (in their current order), followed by unselected faces in the original order. This is done by re-appending existing DOM elements to `#pick-grid` via `reorderGrid()`.

### Face Registry

Instead of hardcoding `FACES` inside `pick-page.ts`, the build-time code generator script constructs [faces-list.ts](file:///Users/spucci/chronometer-web/src/faces/generated/faces-list.ts) automatically. `pick-page.ts` imports this list dynamically to populate the picker's grid and selection layout, ensuring that the picker registration and the active faces in `faces.txt` are always kept in sync.

### Dynamic Favicon and Apple Touch Icon Background

The picker page (`pick.html`), selected faces page (`selected.html`), and all-faces page (`all.html`) dynamically generate their browser favicons and iOS home screen icons based on the currently selected or loaded watch faces:

* The watch face thumbnails are composited dynamically into a single icon (diagonal layout for 2 faces, asymmetric triangle packing for 3, and a 2x2 grid for 4+ faces).
* The background of the generated icon is calculated as the arithmetic average of the individual watch face bezel-matched background colors (ignoring invalid or unparsed colors), creating a harmonious backdrop on iOS home screens.

## Selected Faces Page (`selected.html`)

Built from `face-template.html` with all face scripts (identical to `all.html`). The engine filters and reorders faces at runtime.

### Engine Logic (`engine-entry.ts`)

At startup in `main()`:

1. Detect `selected.html` via `window.location.pathname`
2. If `picks` param is present:
   - Parse the concatenated abbreviation codes
   - Filter `faceDataArray` to matching faces
   - Reorder to match the `picks` order
   - If no faces match, fall back to showing all
3. If no picks (`getState().picks` empty): redirect to `pick.html`
4. Add `is-selected-faces` CSS class to `<body>` (instead of `is-all-faces`)

### Edit Picks Button

An "Edit Picks" text link (`#edit-picks-link`) is visible only on `selected.html` via the CSS rule `body.is-selected-faces #edit-picks-link { display: flex }`. It links to `pick.html` (any current query string is preserved for the URL-fallback case).

## Adding a New Face

When adding a new watch face:

1. Add a unique 2-letter `urlAbbrev` attribute, a `displayName`, and a `description` to the new face's XML `<watch>` element.
2. Add the face folder/slug name (e.g. `basel-clone`) to [faces.txt](file:///Users/spucci/chronometer-web/faces.txt).
3. The build system automatically validates the abbreviation uniqueness, generates the typescript files, compiles the assets, and injects the new face into the picker.
